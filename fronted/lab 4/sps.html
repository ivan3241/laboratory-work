Архитектурный контекст

Сложная программная система (СПС) состоит из множества взаимодействующих компонентов: интерфейсов, сервисов, баз данных и средств мониторинга. Главная задача инженера — сделать такую систему понятной, надёжной и сопровождаемой.

Сложность нельзя убрать полностью, но её можно разделить на понятные части.

— принцип разделения ответственности

Слои архитектуры

  1. Уровень представления
    • веб-интерфейс и панели мониторинга
    • HTML, CSS, JavaScript
  2. Уровень бизнес-логики
    • серверные сервисы и API
    • обработка запросов и правил предметной области
  3. Уровень данных
    • реляционные и нереляционные базы данных
    • кэширование и очереди сообщений

Интерфейсы

Компоненты обмениваются данными через чётко определённые интерфейсы:

  • Web-интерфейс→API-шлюзREST, JSON
  • API-шлюз→База данныхSQL
  • Мониторинг→API-шлюзметрики Prometheus

Технологический стек

Frontend:
HTML5, CSS3, адаптивная вёрстка (Flexbox, Grid).
Инструменты:
Visual Studio Code, Git, инструменты разработчика в браузере.
Контроль качества:
валидация кода, проверка на разных устройствах.

Направления развития

  • Наблюдаемость

    Восстановить мониторинг и настроить оповещения.

  • Надёжность

    Устранить предупреждение базы данных, добавить резервирование.

  • Автоматизация

    Проверки кода и сборка при каждом изменении.

  • Доступность

    Контрастные интерфейсы и проверка на разных устройствах.

Безопасность

Интерфейсы сложных систем должны быть контрастными и читаемыми: оператор не должен ошибиться из-за плохой вёрстки.
